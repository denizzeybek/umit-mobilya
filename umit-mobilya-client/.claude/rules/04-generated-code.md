# Rule 04 — Generated code

> If a file was produced by a tool, the tool is the source of truth. Editing the output edits nothing.

## Why this rule exists

One generated file already exists here and gets hand-edited by mistake:
`components.d.ts`. It is written by `unplugin-vue-components` on every build and
opens with `/* eslint-disable */` and `// @ts-nocheck` — the plugin itself is
telling you not to treat it as source. Edits survive until the next `yarn build`,
then vanish, having polluted the diff in the meantime.

`src/client/` is the other one, and it is the bigger prize: 43 files of typed
API client generated by `openapi-typescript-codegen` from the backend schema.
It is ignored in `eslint.config.js` and denied for `Edit`/`Write` in
`.claude/settings.json`, so an agent cannot hand-patch it even by accident.

## Regenerating

```bash
cd umit-mobilya-server && yarn schema:dump   # writes openapi.json
cd umit-mobilya-client && yarn gcl           # regenerates src/client from it
```

`openapi.json` is committed, so `yarn gcl` works with no server and no
database. `yarn gcl:live` points at `http://localhost:3000/docs-json` instead,
for when the server is already running — note that the server only listens on
3000 if `PORT` says so (`.env.example` does; the code default is 5000).

The dump has to go through `nest build` — the `@nestjs/swagger` CLI plugin is a
TypeScript transformer, and running the dumper through `ts-node` produces a
schema where every model is an empty object. The endpoints still appear, which
is what makes the failure easy to miss.

Because `openapi.json` is committed, a contract change shows up as a reviewable
diff. Treat an unexpected one as a question, not as noise.

## Do

1. Treat `components.d.ts` as build output. Let `unplugin-vue-components`
   regenerate it; ignore its churn in diffs.
2. Regenerate `src/client/` with `yarn gcl` rather than touching the files. If
   the output is wrong, the schema is wrong.
3. Configure the generated client from outside it — `src/plugins/apiClient.ts`
   sets `OpenAPI.BASE` and `OpenAPI.TOKEN`. Never edit `src/client/core/`.
4. Fix problems at the source. A wrong type in generated output means the backend
   schema is wrong — fix the DTO, regenerate, and the fix reaches every consumer.
5. Import generated types from `@/client` and delete the hand-written equivalent
   in `src/interfaces/` once the generated one covers it. Two copies of a type
   drift apart silently.
6. Put endpoints the schema does not describe into a separate `src/customClient/`
   layer, mirroring the shape of the generated services. Keeping them out of
   `src/client/` means a regeneration never destroys them.

## Don't

- ❌ Hand-edit `components.d.ts`.
- ❌ Hand-edit anything under `src/client/` — including "just this one type".
  The next `gcl` run overwrites it.
- ❌ Commit a `src/client/` change without the `openapi.json` change that
  produced it. They travel together or the next regeneration reverts you.
- ❌ Patch a generated type locally to make a component compile. That hides a
  contract mismatch that will bite the next consumer.
- ❌ Add `src/client/` files to a commit by hand-writing them. They arrive only
  from the generator.
- ❌ Mix hand-written code into the generated directory as a shortcut. That is
  what `src/customClient/` is for.

## Also generated, also committed

- `components.d.ts` — `unplugin-vue-components`
- `tsconfig.*.tsbuildinfo` — TypeScript incremental build state; gitignored,
  because it churned on every build and kept leaking into unrelated commits
- `dist/` — Vite build output; gitignored despite existing locally
- `src/client/**` — `openapi-typescript-codegen`, from
  `umit-mobilya-server/openapi.json`
